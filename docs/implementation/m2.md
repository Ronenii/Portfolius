# M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add instrument search/autofill, daily price refreshes, and multi-dimensional portfolio allocation breakdowns so a signed-in user can quickly add real assets and see current market values, data freshness, and exposure across instruments, asset classes, sectors, countries, regions, and currencies.

**Architecture:** The backend remains the source of truth for instrument metadata, prices, market values, and allocation percentages. Instrument lookup and market data are wrapped behind local integration interfaces that can be mocked in tests and backed by Financial Modeling Prep and `yfinance` in production. The frontend reads protected endpoints through the existing bearer-token API client, uses instrument search to prefill the holdings form, and renders a practical dashboard with summary metrics, freshness state, and breakdown tables/charts.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, httpx, pytest, Financial Modeling Prep, yfinance, React, Vite, TypeScript, TanStack Query, Recharts, Vitest.

- Automatic background workers hosted inside the FastAPI process. Scheduling is handled externally by GitHub Actions or platform cron.
- Investment advice, recommendations, or rebalancing suggestions.

M2 is complete when:

- Alembic upgrades a clean database to include the `prices` table and uniqueness/index constraints.
- Price rows are unique per `instrument_id`, `price_date`, and `source`.
- Instrument search is protected by auth, debounced in the frontend, and returns matching symbols/names without requiring the user to type exact ticker symbols.
- Selecting an instrument search result fills symbol, name, exchange, currency, asset class, sector, country, and region when provider metadata is available.
- `yfinance` calls are isolated behind a mockable client; tests do not hit the network.
- Refreshing prices only touches instruments currently used by the authenticated user.
- Protected portfolio and refresh endpoints return `401` without auth.
- Portfolio snapshot math is deterministic and covered by unit tests.
- Breakdown percentages sum to 100 within each currency after rounding for priced holdings.
- Holdings with missing prices are surfaced explicitly and excluded from market-value allocation percentages.
- The dashboard shows loading, empty, missing-price, and priced portfolio states.
- Backend and frontend lint, tests, and production build pass.
- README and `.env.example` files document the scheduler secret and market-data behavior.

## Data Contracts

### Instrument Search Response

`GET /api/v1/instruments/search?query=IN` returns up to 10 authenticated lookup results:

```json
[
  {
    "symbol": "INDA",
    "name": "iShares MSCI India ETF",
    "exchange": "BATS",
    "currency": "USD",
    "asset_class": "ETF",
    "sector": "Broad Market",
    "country": "India",
    "region": "Asia",
    "source": "fmp"
  }
]
```

Search behavior:

- Query strings shorter than two trimmed characters return an empty list.
- Results are ranked by exact symbol prefix first, then provider order.
- The frontend may show suggestions after the first character from local input state, but it should call the backend only after the debounced query has at least two characters and a 350ms debounce.
- Selecting a result fills the holdings form fields; the user can still edit any field before saving.
- Provider failures return an empty list and a server log entry, not a broken holdings form.

### Price Model

`prices` stores daily close prices:

- `id`: integer primary key.
- `instrument_id`: foreign key to `instruments.id`, required.
- `price_date`: calendar date for the close price, required.
- `close_price`: numeric value greater than or equal to zero, required.
- `currency`: three-letter ISO currency code copied from the provider or instrument, required.
- `source`: provider name such as `yfinance`, required.
- `created_at`: timestamp, required.

Constraints:

- Unique: `instrument_id`, `price_date`, `source`.
- Index: `instrument_id`, `price_date`.
- Index: `price_date`.

## Implementation Notes

- Keep all portfolio math independent from FastAPI route functions so it remains easy to unit test.
- Use `Decimal` in backend calculations and serialize numbers as strings to avoid frontend floating-point surprises in API contracts.
- Do not call yfinance from tests. Use fake clients or monkeypatched provider objects.
- Do not hide missing prices. M2 is more trustworthy when it shows coverage explicitly.
- Do not introduce FX conversion until a later milestone adds a reliable currency-rate source and clear conversion dates.
- Do not broaden scheduled refresh to every user until the product has account administration and operational limits.
